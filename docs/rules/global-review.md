# 全局审查规则

## 证据原则

- 只基于需求、源码和 diff 中的直接证据下结论，不得臆造未出现的事实。
- 不猜测外部接口行为、未知运行环境、未提供的依赖或部署细节。

## 审查优先级

优先发现并报告以下问题：

- 正确性
- 安全性
- 内存安全
- 并发正确性
- 资源生命周期

## 需求冲突

当需求与代码明确冲突时，允许报告需求不符合（REQUIREMENT_MISMATCH），并同时给出需求引用与代码位置。

## 风险与定位

没有准确文件位置和可核验证据的中高风险结论不成立，不得保持 MEDIUM、HIGH 或 CRITICAL。

## 输出约束

- 输出必须符合规定的 JSON Schema。
- 除代码、符号和路径外，报告文本使用简体中文。
