# C/C++ 审查规则

审查 C/C++ 源码时，按下面的检查动作核对。这些是已出现过的通用缺陷，不依赖项目专属宏、固定目录或数据库方言。仅基于本次输入中的证据报告问题。

优先覆盖：未初始化与未定义行为；空指针、悬空指针、use-after-free、重复释放；数组和缓冲区越界；整数溢出、符号转换和长度回绕；资源所有权与 RAII；返回值和错误码；数据竞争、死锁和错误内存序；信号、线程和进程生命周期；外部输入长度校验。同一根因只报告一次。

## 原子与内存序

- 区分普通变量、`volatile`、原子变量、锁、条件变量各自保护的状态。`volatile` 不提供原子性、互斥或线程间顺序。
- 先写数据再设完成标志时，写端需要 release，读端需要 acquire。relaxed 计数不会自动发布旁边的普通数据。
- 锁至少要建立 acquire/release。循环退出后的 relaxed load 不等于 acquire。
- 多个原子字段组成一个状态时，检查是否需要一致快照。单字段原子不保证跨字段不变量。
- 共享内存中的原子要核对生命周期、对齐、类型、lock-free 属性和跨进程实现是否真有保证。

## 竞争与对象生命周期

- 一个线程释放、清空、重建或关闭对象时，另一个线程是否仍在发送、解析、回调或轮询。
- 锁必须覆盖“查找对象、固定生命周期、使用对象”的完整区间。只锁 map 查找然后返回裸指针通常不够。
- 超时、重连和停止之后的迟到回调，不得访问已释放或已复用的数组、socket、解包句柄和用户对象。
- 移除回调与正在执行的回调之间，必须有 drain、join、引用计数、epoch 或等价同步。
- 异常和提前返回不得让手工 `lock()` 永远不 `unlock()`。优先使用 RAII。

## 等待、活锁与死锁

- 自旋循环必须有 pause、yield 或退避，以及超时、停止标志和对端是否存活的检查。
- 队列满、等待清空、重连、进程退出和共享标志等待，要验证对端停滞时会怎样。
- 在非原子共享变量上 sleep 或 poll 仍然是数据竞争。等待条件必须正确同步。
- 检查锁顺序、回调内重入、读锁重入，以及锁内阻塞的远程调用。

## 共享内存与进程间同步

- attach 前验证 magic、版本、总长度、元素大小、槽数、最大元素数和初始化完成标志。不能用当前进程的新配置重算已有共享内存里的内部指针，除非与共享头的几何完全一致。
- `mmap` 前用文件实际长度核对映射长度。映射长于文件时，访问可能触发 SIGBUS。
- 仍有存活附着者时，不得无条件清空、缩小或重建共享 ring buffer。
- 初始化应先写内容，最后用 release 写 ready 或 magic；附着者用 acquire 读取。
- 进程共享锁不自动处理持锁进程死亡。关键共享锁要评估崩溃后是否永久占锁，以及是否有恢复路径。自制 CAS 锁要能识别持有者并支持超时或接管。
- 跨进程普通整数读写要核对原子性、对齐和内存序。未对齐的 64 位值可能撕裂。
- 创建者崩溃、附着者仍存活、配置或版本变化、初始化写到一半崩溃时，恢复路径必须比普通路径更保守，不能依赖可能已损坏的共享数据。检查是否破坏仍在使用的状态、是否丢弃在途消息，以及是否有 generation 或 owner 标识。

## 信号与进程、线程生命周期

- 在信号处理链上递归追踪调用。日志、`malloc`/`new`、`std::string`、iostream、mutex、`sleep`、`system()` 和大多数库函数都不是 async-signal-safe。
- 崩溃信号处理函数只应设置 `sig_atomic_t` 或无锁标志、向预先打开的 fd 写固定数据，或恢复默认处理后再用 `kill`/`raise` 重发。不得获取可能被中断线程持有的锁，也不得访问需要动态分配的全局对象。
- 崩溃记录用的预分配数组，索引和回绕必须有边界。错误路径不能再次越界。
- `fork()` 的返回值先保存为 `pid_t`，分别处理小于 0、等于 0、大于 0。不可先存进无符号字段。
- 任何 `kill` 之前确认 pid 大于 0，避免 `kill(-1)` 广播和 `kill(0)` 发给整个进程组。
- 子进程 `exec` 失败后使用 `_exit`，避免刷新或释放从父进程继承的用户态状态。多线程进程 `fork` 之后、`exec` 之前，只能调用 async-signal-safe 操作。
- `waitpid` 要检查返回值，用 `WIFEXITED`、`WIFSIGNALED`、`WIFSTOPPED` 判断后再读状态。
- `pthread_create` 等 pthread API 的错误在返回值里，不一定写入 `errno`。
- 停止顺序应是 stop、join 或 drain、close、delete，并且重复调用幂等。所有线程都要能看到停止标志，并从阻塞等待中被唤醒。
- 部分初始化失败后的析构，只能访问已经初始化的成员。检查守护进程重启次数、退避和子进程反复崩溃时的资源上限。

## 外部输入与内存边界

- 第一次解引用或拷贝前，先验证固定头长度，再验证动态头和 body。
- 用 `head <= total && body <= total - head`，不要先算可能溢出的 `head + body`。
- `size_t` 减法前确认被减数不小于减数。负数转无符号前保留错误判断。
- 拷贝长度以目标容量为上限，并显式保证字符串以 NUL 结尾。
- `snprintf` 的返回值是所需长度，可能大于等于缓冲区容量，不能直接当作已写入长度去偏移。
- 扩展头要检查最小和最大长度、对齐、每次循环推进量和剩余空间。
- 有符号索引同时检查小于 0 和大于等于个数。注意 -1、-2 这类哨兵。序号、哈希或配置推导出的索引，在最终数组处再验证一次。
- `vector[0]`、取模、除法或 `count - 1` 之前，证明容器或计数非零。
- 检查 NULL 传入 `std::string`、`strchr`、`strlen`，以及二进制 buffer 被当成 C 字符串。
- 检查初始化前读取、释放后未置空、容器删除后残留的指针、重复 close、delete 或 unmap。
- `new[]`/`delete[]`、`new`/`delete`、`malloc`/`free` 和第三方 create/destroy 必须成对。扩容失败后旧指针仍须可用，不能先覆盖唯一指针再判断 NULL。
- 检查循环里覆盖成员资源指针、错误路径提前返回，以及半初始化对象的清理。
- 回调不得保存栈对象、临时字符串或 vector 元素的地址，除非能证明其生命周期覆盖回调。

## 协议与状态机

- 分别看组合路径：分页加压缩、分片加队列满、订阅加重连、超时加迟到应答。
- 每个循环分支都要推进游标或显式退出，尤其是 `continue`、未知扩展头和跳过坏包。
- 解压后的 buffer 和长度不能和原始 buffer、长度交叉使用。
- 分片需要消息 ID、序号、来源以及 FIRST/LAST 一致。中间失败要清理半包并保留正确错误码。
- 共享的解码句柄或游标，在递归、嵌套和跨线程使用时必须有独立状态或同步。
- 坏包、断连、重连、切主和停止之后，epoll 注册、socket 指针、连接和心跳状态必须一致。
- 超时取消后，阻止迟到应答写入已释放槽位。通常需要 generation 或 request ID，以及取消握手。
- 清理函数既要释放元素，也要清空容器并重置游标。重复 Open、Close、Clean 应幂等。

## 错误处理与失败原子性

- 检查系统调用、库函数和回调的返回值。区分错误、部分成功、EOF、EINTR、EAGAIN 和超时。
- `read`、`write`、`send`、`recv` 要处理短读短写。对 EINTR 明确重试或向上传播。
- `std::stoi` 一类可能抛异常的转换，不能无界逃出 C 边界或线程入口。
- 普通 `new` 默认抛异常。返回 NULL 的分配器必须处理 NULL。
- 只在 API 约定会设置 `errno` 时才读它。返回错误码的 pthread、JNI 或第三方 API 不要误读 `errno`。
- 失败路径回滚已经更新的计数、注册、队列、map、fd、锁和状态，不能留下看起来成功的半初始化对象。
- 返回码类型必须能表达负的错误值，避免用 `size_t` 或 `uint32_t` 接收负数。
- 不能吞掉队列满、外部上报失败或部分发送这类关键错误。

## 长稳与资源生命周期

- 为 fd、mmap、共享内存、锁、线程、动态库、socket、报文句柄和第三方对象列出获取与释放，覆盖成功路径、每个失败出口、重试、重连、reload、重复打开关闭和析构。
- 检查 vector、map、list、request ID、缓存和回调表是否只增不删，并按实际请求速率看会不会无限涨。
- 超时和间隔使用单调时钟。检查负间隔、零间隔、过大超时和时间回拨。
- 清理之后重置关联容器、句柄和状态，使重复调用安全。

## JNI 与 CPython

JNI：

- 每次 `Get*ArrayElements` 在所有路径配对 `Release*ArrayElements`。
- 常驻 native 线程正确 Attach 和 Detach。循环里的 local reference 要逐次删除，或使用 local frame。
- 跨回调保存的 Java 对象使用 global 或 weak global reference，并在并发回调结束后再安全删除。
- 可能抛 Java 异常的 JNI 调用之后检查 `ExceptionCheck`。异常挂起时不要继续调用大多数 JNI API。
- 方法签名与调用族一致，避免对 void 方法使用 `CallObjectMethod`。
- `NewStringUTF` 只接受 modified UTF-8。任意字节或其它编码必须先转码。

CPython：

- 分清 borrowed、new、stolen reference。保存 borrowed reference 之前 `Py_INCREF`，释放时 `Py_DECREF`。
- 网络或回调线程访问 Python 对象和全局 map 之前获取 GIL，并同步对象删除与回调执行。
- 数字格式与 C 类型匹配。64 位整数不能用 32 位格式。
- 异常要传播或清理，不能返回成功同时又留下 Python exception。

## 整数与类型转换

- 乘法之前提升到目标宽度，例如先转成 `uint64_t` 再乘。运算完成后再收窄已经太晚。
- 加法、乘法和对齐计算做上界检查。长度减法先验证大小关系。
- 追踪有符号与无符号比较，以及三目表达式的一般算术转换。
- 检查负错误码进入 `size_t` 或 `uint32_t`、64 位序号进入 `int`、指针或句柄进入更窄的整数。
- 检查协议字段截断、计数回绕、时间单位溢出、配置里的负数转无符号。
- 除法和取模之前验证除数大于零。
- 格式化参数与 `%d`、`%u`、`%zu`、`%lld` 匹配。校验和、哈希和二进制字节使用明确的无符号类型。

## 逻辑与可移植性

- 比较字符串内容不能比较指针地址。核对 `strcmp` 的方向和大小写语义。
- 检查悬空 else、宏缺少 `do { } while (0)`、宏参数被重复求值、形参误写成外部变量。
- 复制粘贴的分支重点核对句柄类型、变量名、目标 API、错误码，以及不同角色的资源语义。
- 检查声明的返回值是否每条路径都有、接口长度参数、option 类型和缓存状态是否一致。
- 在 ARM 或 aarch64 上检查弱内存序、未对齐访问、64 位撕裂，以及依赖 x86 强内存序的协议。
- 多字节协议字段显式转换。核对 packing、对齐、char 的符号、整数宽度、`long` 的宽度和格式化。
- 头文件里的非 inline 函数要考虑多个翻译单元的 ODR 和链接行为。
