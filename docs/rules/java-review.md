# Java 审查规则

审查 Java 源码时，重点检查以下通用高价值问题。仅基于本次输入中的证据报告，不引入未在输入中出现的内部约定、固定数据库方言或目录约定。

- 空指针和 Optional 误用。空值、向下转型和异常对象要有明确证据。
- 资源关闭和异常吞噬。连接、流、锁和回调必须在所有路径释放。禁止吞掉异常后继续处于错误状态。
- `ThreadLocal` 必须在 finally、拦截器或等价的请求结束路径中清理。线程池复用线程时，未清理的上下文会串到后续任务。
- 集合修改和并发安全。检查遍历时修改、非线程安全集合的共享访问。
- 静态集合和无界缓存不得只增不减。不得一次性加载无上限的大结果集，也不得在热点路径上无控制地创建大对象。
- 线程池必须有界队列、明确的拒绝策略、停止和任务取消。避免无界线程工厂或无界队列。任务异常要传播或记录，不能丢在线程入口。
- 事务边界和同类自调用导致事务失效。只有输入里能看到事务注解和调用关系时才报告。
- 入参校验：外部输入的空值、长度、范围和格式。
- 金额和高精度：不要用 `double` 直接参与金额计算，也不要 `new BigDecimal(double)`。检查 scale、舍入模式、溢出和输入边界。
- 强制类型转换必须有类型证据，不能靠猜测目标类型。
- 远程调用必须能看到连接超时和读取超时。重试必须有限，并且只有输入里能证明幂等时才把缺少幂等当成问题。
- 魔法数字、废弃代码和调试残留只在改变金额、状态、权限或协议语义时报告。
