# Lua 审查规则

审查 Lua 源码时，只基于本次输入中的证据。未提供的运行时、宿主框架或业务 API 语义不猜测；需要业务契约时由需求或 checklist 提供。

- 区分 `nil` 和 `false`。检查未声明就使用的全局变量、table 键的生命周期、metatable、闭包捕获和错误返回是否被调用方处理。
- 检查协程的 resume 与 yield 是否成对，回调取消后是否仍访问已释放状态，循环是否有终止条件，字符串和二进制长度是否越界，事件或回调是否重复注册又不注销。
- 与 C/C++ 交互时，检查 Lua 栈在每条路径上是否平衡，userdata 的生命周期是否覆盖使用点，错误对象是传播还是被丢掉，整数和浮点转换是否截断，以及非持有运行时的线程是否直接碰 Lua 状态。
